## 1. 백엔드 — `TodoService.get_todos()` 필터 파이프라인 분리 ⭐

### 배경
초기에는 카테고리·우선순위·완료여부 필터가 `get_todos()` 한 함수 안에 인라인으로
나열되어 있었다. 여기에 **검색(search)** 조건을 추가하려 하자, 함수가 더 길어지고
각 필터의 책임 경계가 흐려졌다. → 필터 로직을 단계별 private 메서드로 분리.

### 리팩터링 전 (Bad)
```python
def get_todos(self, category, priority, done):
    todos = self._repo.get_all()
    if category is not None:
        todos = [t for t in todos if t.category == category]
    if priority is not None:
        todos = [t for t in todos if t.priority == priority]
    if done is not None:
        todos = [t for t in todos if t.done == done]
    return todos
```
- 조건이 늘어날수록 함수 길이가 증가
- 각 필터 로직이 한 덩어리에 섞여 책임이 불분명
- 검색 같은 새 조건 추가 시 이 함수를 계속 수정해야 함

### 리팩터링 후 (Good)
```python
def get_todos(self, category=None, priority=None, done=None, search=None):
    todos = self._repo.get_all()
    return self._apply_filters(todos, category, priority, done, search)

# ── Private (캡슐화된 내부 필터 로직) ──
def _apply_filters(self, todos, category, priority, done, search):
    todos = self._filter_by_category(todos, category)
    todos = self._filter_by_priority(todos, priority)
    todos = self._filter_by_done(todos, done)
    todos = self._filter_by_search(todos, search)
    return todos

def _filter_by_category(self, todos, category): ...
def _filter_by_priority(self, todos, priority): ...
def _filter_by_done(self, todos, done): ...
def _filter_by_search(self, todos, search):
    if not search:
        return todos
    keyword = search.casefold()  # 대소문자 무시
    return [t for t in todos
            if keyword in t.title.casefold()
            or keyword in t.description.casefold()]
```

### 효과
| 관점 | 개선 내용 |
|---|---|
| **가독성** | `get_todos()`가 "전체 조회 → 필터 적용" 2줄로 의도가 한눈에 보임 |
| **유지보수성** | 검색 로직 변경 시 `_filter_by_search()`만 수정 |
| **캡슐화** | `_` prefix로 필터 구현 세부사항을 외부에 은닉 |
| **확장성(OCP 지향)** | 새 필터는 `_filter_by_*()` 추가 + 파이프라인 한 줄 연결로 끝 |
| **테스트 용이성** | 각 필터를 독립적으로 단위 테스트 가능 |

### 관련 OOP 원칙
`[SRP]` 서비스는 로직만 · `[캡슐화]` private 메서드 · `[리팩터링]` 파이프라인 분리

### 동작 보장 (리팩터링 전후 동일성)
`tests/test_todo.py`에 다음 테스트를 추가하여 리팩터링 후에도 동작이 동일함을 검증:

## 2. 프론트엔드 — 필터 로직을 `FilterManager`로 분리

### 배경
초기에는 필터 값 읽기/이벤트 바인딩이 `TodoApp` 안에 섞여 있어, "앱 조율"과
"필터 상태 관리"라는 두 책임이 한 클래스에 공존했다 (SRP 위반).

### 전 → 후
```javascript
// [전] TodoApp 내부에 필터 DOM 접근 + 값 조합이 혼재
class TodoApp {
  refresh() {
    const category = document.getElementById('filter-category').value;
    const priority = document.getElementById('filter-priority').value;
    // ... 필터 값 직접 조합
  }
}

// [후] 필터·검색 책임을 전담하는 별도 클래스로 분리
class FilterManager {
  #bus;  // [캡슐화] private 필드
  getFilters() {
    return { category, priority, done, search };  // 필터 값 조합 전담
  }
  bindEvents() {
    // 드롭다운 change → 'filter.changed' 발행
    // 검색창 input  → 'search.changed' 발행 (실시간 검색)
  }
}
```

### 효과
- `TodoApp`은 "조율(Facade)"에만 집중, `FilterManager`는 "필터 상태"에만 집중 → **SRP 회복**
- 필터 UI가 바뀌어도 `FilterManager`만 수정

### 관련 OOP 원칙
`[SRP]` 단일 책임 · `[Observer]` 버스 이벤트로 느슨한 결합

## 3. 프론트엔드 — public → `#private` 캡슐화 강화

JS의 `#` private 필드/메서드를 사용해 "외부에서 호출하면 안 되는 내부 구현"을
문법적으로 차단했다 (기존 `_` 관례는 접근을 막지 못함).

| 대상 | 전 | 후 | 이유 |
|---|---|---|---|
| `TodoRenderer.createCard()` | public | `#createCard()` | 개별 카드 생성은 내부 전용 — 외부 직접 호출 차단 |
| `TodoRenderer.getDdayText()` | public | `#getDdayText()` | D-day 계산은 카드 렌더링 보조용 내부 로직 |
| `FrontEventBus._listeners` | 일반 속성 | `#listeners` | 구독자 목록을 외부에서 조작 못 하게 보호 |
| `TodoAPI.baseURL` | 일반 속성 | `#baseURL` | 서버 주소 등 내부 구성 은닉 |

```javascript
class TodoAPI {
  #baseURL;                      // 외부에서 app.api.#baseURL 접근 → 문법 에러
  constructor(baseURL) { this.#baseURL = baseURL; }
}

class TodoRenderer {
  render(todos) {
    todos.forEach(t => this.container.appendChild(this.#createCard(t)));
  }
  #createCard(todo) { ... }      // 내부 전용
  #getDdayText(dueDate) { ... }  // 내부 전용
}
```

### 효과
- 호출자는 **공개 API(`render`, `getAll`, `on/emit`)** 만 알면 됨
- 내부 구현 변경이 외부에 영향을 주지 않음 → 캡슐화로 결합도 감소

### 관련 OOP 원칙
`[캡슐화]` JS `#` private 필드/메서드

## 4. 검색 기능 신규 도입 (리팩터링을 촉발한 변경)

| 계층 | 변경 |
|---|---|
| Service | `get_todos(..., search)` + `_filter_by_search()` (casefold 대소문자 무시) |
| API | `GET /todos?search=` 쿼리 파라미터 추가 |
| Front API | `TodoAPI.getAll({ search })` 쿼리 조립 |
| Front UI | 🔍 검색창 + `oninput` 실시간 검색(`search.changed` 이벤트) |
| Test | 검색 단위 테스트 5종 + 필터·검색 조합 1종 |

검색은 **제목(title)** 과 **설명(description)** 을 모두 대상으로 하며,
`casefold()`로 대소문자를 구분하지 않는다.
