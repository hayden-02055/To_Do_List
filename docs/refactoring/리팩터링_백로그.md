## P1 — OOP 가치가 높은 리팩터링 (보고서 강화용)

### P1-1. 도메인 예외 타입 도입 — `KeyError` 의존 제거 ⭐ 🟡
**문제**: 서비스가 "할일 없음"을 표현하려고 파이썬 내장 `KeyError`를 던지고, API가 이를 404로 번역한다. 도메인 의미가 범용 예외에 얹혀 있어 모호하다.

```python
# 전 (services/todo_service.py)
todo = self._repo.get_by_id(todo_id)
if todo is None:
    raise KeyError(todo_id)        # ← 의미 불명확

# 후 (errors.py 신설)
class TodoNotFoundError(Exception):
    """해당 id의 할일이 존재하지 않을 때."""

# service
if todo is None:
    raise TodoNotFoundError(todo_id)

# main.py
except TodoNotFoundError:
    raise HTTPException(404, "Todo not found")
```
- **관련 원칙**: `[SRP]` 도메인 오류를 도메인 언어로 표현 · 가독성 · 의도 명확화.
- **효과**: 테스트에서도 `pytest.raises(TodoNotFoundError)`로 의도가 또렷해진다.

### P1-2. LSP 행동 일관성 — 저장소 반환 의미 통일 ⭐ 🟡
**문제**: 두 구현의 `get_by_id()` 반환 의미가 다르다.
- `MemoryTodoRepository`: 저장된 객체의 **참조**를 반환 (외부에서 수정하면 저장소 내부도 바뀜)
- `FileRepository`: 파일에서 새로 만든 **복사본** 반환

지금은 `save()`를 항상 호출해 결과가 같지만, "추상 타입을 안전하게 치환 가능"하다는 LSP의 약속이 행동 수준에서 미세하게 깨져 있다.

```python
# 후: Memory도 복사본을 반환해 의미를 통일
def get_by_id(self, todo_id):
    todo = self._store.get(todo_id)
    return todo.model_copy(deep=True) if todo else None
```
- **관련 원칙**: `[LSP]` 인터페이스의 **계약(반환 의미)** 까지 동일하게.
- 보고서 포인트: "LSP는 시그니처뿐 아니라 행동 계약까지 포함한다"는 걸 코드로 보여줄 수 있다.

### P1-3. 이벤트 이름 상수화 — 매직 스트링 제거 🟡
**문제**: `"todo.created"`, `"todo.deleted"` 등 문자열이 백엔드·프론트·테스트에 흩어져 있어 오타가 런타임에야 드러난다. (게다가 백엔드는 `created/completed/deleted`, 프론트는 `added/toggled/deleted`로 네이밍이 불일치)

```python
# 후 (events/event_names.py)
class TodoEvent(str, Enum):
    CREATED   = "todo.created"
    COMPLETED = "todo.completed"
    DELETED   = "todo.deleted"

self._bus.emit(TodoEvent.CREATED, saved)   # 오타 시 즉시 에러
```
- **관련 원칙**: `DRY` · 단일 출처(SSOT). 프론트도 동일 상수 객체로 통일.

### P1-4. Observer 견고성 — 구독자 예외 격리 🟢
**문제**: `emit()`에서 콜백 하나가 예외를 던지면 **이후 구독자가 실행되지 않는다**. Observer의 핵심(발행자-구독자 분리)이 한 구독자 때문에 깨진다.

```python
# 후 (events/event_system.py)
def emit(self, event, data=None):
    for callback in self._listeners.get(event, []):
        try:
            callback(data)
        except Exception as e:
            print(f"[EventBus] '{event}' 구독자 처리 실패: {e}")  # 격리
```
- **관련 원칙**: `[Observer]` 발행자와 구독자의 진짜 독립성 보장.

### P1-5. 프론트 `TodoForm` 클래스 추출 — SRP 대칭 맞추기 🟡
**문제**: 필터는 `FilterManager`로 분리됐는데, **입력 폼 처리는 아직 `TodoApp.bindFormEvents()`에 DOM 접근 + API 호출 + 이벤트 발행이 뭉쳐 있다.** Facade가 다시 비대해지는 중.

```javascript
// 후: 폼 책임을 전담 클래스로
class TodoForm {
  #bus;
  constructor(bus) { this.#bus = bus; this.form = document.getElementById('todo-form'); }
  bindEvents() { /* submit → 검증 → 'todo.submitted' 발행 */ }
}
// TodoApp은 생성/연결만
```
- **관련 원칙**: `[SRP]` `FilterManager`와 동일한 패턴으로 일관성 확보.

## P2 — 선택 / 트레이드오프 기록 (이번엔 보류, 기록만)

### P2-1. `FileRepository` 원자적 쓰기 🟡
- 현재: 매 저장마다 전체 파일을 읽고 통째로 덮어씀. 쓰기 도중 크래시 시 `todos.json` 손상 위험, 단일 워커 전제.
- 개선안: 임시 파일에 쓰고 `os.replace()`로 교체(atomic). 동시성까지 가면 파일 락 필요.
- 판단: **과제 범위 초과.** 회고/한계 섹션에 "단일 워커 전제, 원자적 쓰기 미적용"이라고 한 줄 적는 것으로 갈음 → 오히려 "알고도 스코프를 끊었다"는 인상.

### P2-2. `FileRepository` 매 호출 `_load()` → 캐시 도입 🔴
- 현재: 읽기·쓰기마다 디스크 I/O. 데이터 적어 체감 무.
- 트레이드오프: 캐시는 일관성·무효화 복잡도를 부른다. **지금 넣으면 과한 최적화.** 보류.

### P2-3. `Category(str, Enum)` → `StrEnum` 🟢 / `created_at` UTC화 🟢
- Python 3.11+ `StrEnum`으로 단순화 가능 (선택).
- `datetime.now()` (naive local) → `datetime.now(UTC)` 권장이나 과제 동작엔 무영향.

### P2-4. `EventBus` 전역 싱글턴 제거 🔴
- 현재: 모듈 전역 `event_bus`. 테스트는 별도 버스를 새로 만들어 회피 중.
- 개선안: 앱 시작 시 생성해 `app.state`로 주입(완전한 DI). DIP를 끝까지 밀어붙이는 모범.
- 판단: 구조 변경 폭이 커서 마일스톤 2 후반 or 보류.
